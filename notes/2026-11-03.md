# useReadContract 的 args 参数

## 1. 为什么查 Aave 利率要传 WETH 的地址

关键点：**Aave V3 的 Pool 不是一个币一个合约，而是一个合约管所有币。**

```
Aave V3 Pool（所有网络都只有一个地址，比如 Sepolia 是 0x6Ae43d32...）
  ├── WETH 储备 → 有自己的存款利率
  ├── USDC 储备 → 有自己的存款利率
  ├── DAI  储备 → 有自己的存款利率
  └── WBTC 储备 → 有自己的存款利率
```

合约函数是：

```solidity
getReserveData(address asset) → (ReserveData)
```

`getReserveData` 的意思是「取某条储备的数据」，它必须先知道取哪一条，否则不知道返回哪个币的利率。所以 `wethAddress` 就是在回答「我要 WETH 这一条」。

两个地址别搞混：

| 变量 | 例子 | 作用 | 放在哪 |
|---|---|---|---|
| `poolAddress` | `0x6Ae43d32...` | 合约在哪（代码位置） | `address` 字段 |
| `wethAddress` | `0xC558DBdd...` | 查哪个币（数据条件） | `args` 字段 |

`wethAddress` 是 WETH 这个**代币合约**的地址，不是用户钱包地址。

类比 SQL：

```sql
SELECT * FROM pool WHERE asset = '0xC558DBdd...'
--                      ↑ args 就是这里的 WHERE 条件
```

换成大白话读这段代码：去 `poolAddress` 这个合约，调用 `getReserveData`，问它「WETH 现在什么情况？」，然后从返回结果里取出 `currentLiquidityRate`（存款利率）。

## 2. args 的具体用法

**args 就是函数调用括号里的参数。**

```solidity
// Solidity
pool.getReserveData(wethAddress)
//                    ↑ 这个
```

```ts
// wagmi
useReadContract({
  address: poolAddress,            // 调哪个合约
  functionName: 'getReserveData',  // 调哪个函数
  args: [wethAddress],             // 括号里传什么 ← 就是 args
})
```

规则：**数组，按 ABI inputs 的顺序排，一个不能多一个不能少。**

```ts
// 无参函数：totalSupply()
// 不写 args，或 args: []

// 单参：balanceOf(address owner)
args: [userAddress]

// 多参：withdraw(address asset, uint256 amount, address to)
args: [wethAddress, amount, to]
//     第1个      第2个    第3个   ← 顺序必须和 ABI inputs 一致，反了就是灾难
```

类型收窄（AaveRate.tsx 里那个三元）：

```ts
// getTokenAddress 返回 Address | undefined
args: [wethAddress]                              // ❌ TS 报错：undefined 不能赋给 Address
args: []                                         // ❌ TS 报错：长度不匹配
args: wethAddress ? [wethAddress] : undefined    // ✅ 类型通过
```

因为 ABI 用了 `as const`，viem 推出来的类型就是 `readonly [asset: 0x${string}]`，参数名 `asset` 会出现在 TS 报错提示里。

两个额外特性：

- **args 会进 queryKey**，参数变了（比如切网络后 WETH 地址变了）会自动重新请求，不用手动 refetch。
- **args: undefined 不会禁用查询！** wagmi v3 的 `enabled` 只判断 `address`、`abi`、`functionName`，不看 args。args 为 undefined 时请求照样发出，viem 编码阶段发现少参数直接抛错。想真正跳过请求要显式写：

```ts
query: { enabled: Boolean(wethAddress) }
```

## 3. ABI 入参的三个字段：internalType / name / type

```ts
inputs: [
  { internalType: 'address', name: 'asset', type: 'address' },
]
```

| 字段 | 含义 | 影响什么 |
|---|---|---|
| `type` | ABI 编码用的标准类型（`address`、`uint256`、`tuple`、`uint8`…） | **真正决定 calldata 怎么编码**，viem/ethers 只认这个 |
| `internalType` | Solidity 源码里的原始类型，可以带 struct / contract / enum 名 | 只做文档说明，编码时被忽略 |
| `name` | 参数名（人类可读） | 不影响 calldata；但影响 viem 解码返回值时的对象字段名 |

两者什么时候不一样：

```ts
// 合约类型 → 编码成普通地址
{ internalType: 'contract IERC20', name: 'token', type: 'address' }

// struct → 编码成 tuple
{ internalType: 'struct DataTypes.ReserveData', name: 'reserveData', type: 'tuple' }

// enum → 编码成 uint8
{ internalType: 'enum DataTypes.InterestRateMode', name: 'mode', type: 'uint8' }
```

**type 是沟通合约的协议，internalType 是给人看的注释。**

### name 的实际作用（本项目踩过的坑）

`getReserveData` 的返回值是一个顶层 tuple。如果没给顶层 tuple 写 `name`，viem 会把返回值解码成数组，只能 `data[0]`、`data[1]` 这样取；写了 `name: 'reserveData'` 之后就能 `data.currentLiquidityRate`、`data.aTokenAddress` 这样按字段名取。见 `src/abis/aavePool.ts` 里的注释。

### 完整实例

```ts
// 合约：getReserveData(address asset)
const { data } = useReadContract({
  address: '0x6Ae43d3271ff6888e7Fc43Fd7321a503ff738951', // Sepolia Aave Pool
  abi: AAVE_POOL_ABI,
  functionName: 'getReserveData',
  args: ['0xC558DBdd856501FCd9aaF1E62eae57A9F0629a3c'], // asset = WETH
  chainId: 11155111,
})

// 返回：
// data.currentLiquidityRate  → bigint，1e27 精度，除以 1e27 * 100 得到百分比
```

类型不匹配也会在编码阶段报错，比如 `uint256` 必须传 `BigInt`，传字符串 `'100'` 或 `100` 都不行：

```ts
args: [wethAddress, parseEther('100'), userAddress] // ✅
args: [wethAddress, '100', userAddress]             // ❌ 编码失败
```
